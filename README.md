# SNTO 礼品库存申领系统 · 施工手册（路线2 定稿）

> 2026-10-02 定稿。为什么走路线2：本租户 Lark（国际版）Base 自动化没有「发送审批」节点，  
> 且查找引用对关联字段的等值匹配不可用，因此库存校验/汇总/通知由服务器脚本接管，Base 只做数据 + 按钮。

## 架构

```
申请人 ──表单──▶ [申领表] ──审批人点按钮──▶ 状态=已通过/已拒绝（Base自动化，发消息给申请人）
                    ▲
                    │ 脚本 gift_sync.py（服务器，30s 轮询）
                    ├─ 新单：回填 礼品名称/当前可用
                    ├─ 校验：不足→状态=库存不足+❌群通知；足→状态=待审批+📋群通知
                    ├─ 重算各批次已通过合计 → 写回库存表「已批领用」
                    └─ 超领保护：通过时库存已被占用的单自动回退⚠️
[库存表]：可用数量 = 入库数量 − 已批领用（公式，实时）
```

本目录文件：

| 文件                    | 用途                                        |
| --------------------- | ----------------------------------------- |
| `gift_sync.py`        | 同步脚本（服务器常驻，仅依赖 requests）                  |
| `setup_tables.py`     | 自动建表脚本（本地跑一次，已实测可用）                       |
| `config.example.json` | 配置模板（实际 config.json 含凭证，已被 .gitignore 排除） |
| `gift-sync.service`   | systemd 服务文件                              |
| `.gitignore`          | 已忽略 config.json（含 secret，绝不入库）            |

## 第一部分 · Lark 侧（你操作，约40分钟，顺序勿乱）

### Step 1 建通知群 + Webhook（3分钟）

1. Lark → 消息 → 「+」→ 创建群组，名称**礼品申领通知**
2. 成员：你 + 审批人（+其他想被通知的人）
3. 群设置 → 群机器人 → 添加机器人 → **自定义机器人 Custom Bot** → 添加
4. 复制弹出的 **Webhook 地址**，填进 `config.json` 的 `webhook_url`（签名校验不用开）

### Step 2 应用（0分钟，复用现有的）

**不新建应用、不加权限、不发版。** 复用 KPI agent 那个自建应用（2026-10-02 已实测具备 bitable 读写权限），只需在 Step 5 把它加为新 Base 的协作者。通知走 Step 1 的 Webhook，不需要 IM 权限。它原有的 KPI 功能不受任何影响——礼品脚本只读写礼品 Base。`config.json` 里凭证已就位。

### Step 3 建正式 Base（5分钟）

新建多维表格**礼品库存管理**（会自带一个默认空表，删掉或无视）。按 Step 5 把应用加为协作者后，跟我说一声，我跑 `setup_tables.py`：两张表和绝大部分字段**自动建好**（已实测）。只有下表 ⚠️ 标记的 4 个字段 API 建不了，UI 手动加（各 30 秒）：

**表1 · 礼品库存**

| # | 字段      | 类型 | 配置                                                                         |
| - | ------- | -- | -------------------------------------------------------------------------- |
| 1 | 礼品名称    | 文本 |                                                                            |
| 2 | 品质      | 单选 | S/A/B/C，各配色                                                                |
| 3 | 生产日期    | 日期 |                                                                            |
| 4 | 图片      | 附件 |                                                                            |
| 5 | 入库数量    | 数字 | 整数，盘点时可改                                                                   |
| 6 | 批次号 ⚠️  | 公式 | 手动建：`礼品名称&"-"&品质&"-"&DATESTR(生产日期)`（DATESTR 不识别就换 TEXT(生产日期,"YYYY-MM-DD")） |
| 7 | 已批领用    | 数字 | 脚本写，**勿手改**                                                                |
| 8 | 可用数量 ⚠️ | 公式 | 手动建：`入库数量-已批领用`                                                            |

**表2 · 礼品申领**

| #  | 字段    | 类型   | 配置                         |
| -- | ----- | ---- | -------------------------- |
| 1  | 单号    | 自动编号 | 有格式选项就设 `LP-0001` 样式，没有用默认 |
| 2  | 申请人   | 创建人  | 自动带出                       |
| 3  | 用途    | 单选   | 按实际（客户拜访/展会/内部活动…）         |
| 4  | 申领数量  | 数字   | 整数                         |
| 5  | 审批状态  | 单选   | 待审批/已通过/已拒绝/库存不足，各配色       |
| 6  | 申领时间  | 创建时间 |                            |
| 7  | 关联批次  | 双向关联 | → 礼品库存表（在申领表这边建）           |
| 8  | 礼品名称  | 文本   | 脚本回填                       |
| 9  | 当前可用  | 数字   | 脚本回填（提单时快照）                |
| 10 | 通过 ⚠️ | 按钮   | 手动建：绿色，Step 4 绑自动化         |
| 11 | 拒绝 ⚠️ | 按钮   | 手动建：红色，Step 4 绑自动化         |

**视图**：

- 库存表：画廊视图（封面=图片，标题=礼品名称）；筛选视图「有货」= 可用数量 > 0
- 申领表：筛选视图「待审批」= 审批状态 为 待审批 ← **审批人的工作队列**
- 申领表：表单视图，字段只放**关联批次、申领数量、用途**，申领数量必填，开启分享（链接/二维码发给全公司）

### Step 4 两条按钮自动化（10分钟）

入口：Base 顶部「自动化」→ 创建。

| 自动化  | 触发         | 动作1             | 动作2                                                      |
| ---- | ---------- | --------------- | -------------------------------------------------------- |
| A·通过 | 点击按钮 →「通过」 | 修改当前记录：审批状态=已通过 | 发 Lark 消息 → 收件人=当前记录的创建人：`✅ 你的申领 {单号}（{礼品名称}×{申领数量}）已通过` |
| A·拒绝 | 点击按钮 →「拒绝」 | 修改当前记录：审批状态=已拒绝 | 同上：`⛔ …已拒绝`                                              |

变量用消息编辑框的「+」插入。若动作列表里没有「修改记录」，这两条自动化就只发消息，状态由审批人手动改下拉——功能不损。

### Step 5 权限

1. **应用进 Base**：Base 右上「···」→「添加文档应用」→ 选你 KPI agent 用的那个自建应用 → 权限**可编辑**（找不到入口截图给我）
2. **审批人**：右上「分享」→ 协作者 → 可编辑（点按钮需要）
3. **其他同事**：只给表单链接，不加协作者

### Step 6 取 ID（2分钟）

打开 Base，进入申领表，看浏览器地址栏：

```
https://xxx.larksuite.com/base/APP_TOKEN?table=TABLE_ID&view=...
```

- `app_token` = `base/` 后面那串
- 申领表的 `table=tblXXX`
- 切到库存表，再抄一个 table id

**发我：app_token**（config.json 里凭证已就位，只有这项空着；secret 永远不出现在聊天里）。两个 table_id 在 `setup_tables.py` 跑完后自动给出。

## 第二部分 · 服务器部署（可我来跑，也可照做）

```bash
# 1. 本地上传（server 换成你的服务器）
rsync -av ~/Documents/SNTO/gift-system/ server:/opt/gift-system/

# 2. 服务器上
cd /opt/gift-system
cp config.example.json config.json
vim config.json          # 填 webhook_url / app_token / 两个 table_id（应用凭证已在）
pip3 install requests    # 或 python3 -m pip install requests

# 3. 挂 systemd
sudo cp gift-sync.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now gift-sync
journalctl -u gift-sync -f   # 看到「启动成功」即通
```

> 部署在报销系统同一台腾讯轻量上，互不干扰。⚠️ 该服务器 2026-10-14 到期，先续费。

## 第三部分 · 联调验收

先在库存表造一条测试批次（测试礼品 / S / 2026-09-01 / 入库 10），然后：

| # | 操作                | 预期                                |
| - | ----------------- | --------------------------------- |
| 1 | 表单提单 3            | ≤30s 群收到📋待审批；单子状态=待审批，名称/当前可用已回填 |
| 2 | 审批人点「通过」          | 申请人收✅；库存表 已批领用=3，可用数量=7           |
| 3 | 再提单 5，点「拒绝」       | ⛔；已批领用仍=3，可用仍=7                   |
| 4 | 提单 8              | ❌拦截，状态=库存不足，不进待审批                 |
| 5 | 并发：连提两单各 5，依次都点通过 | 第二单被⚠️自动回退（超领保护生效）                |

五条全过后：删测试数据 → 导入真实库存（Excel 的名称/品质/日期/数量列直接复制粘贴进网格；图片逐行上传，按 SKU 数估时间）→ 发表单链接 → 完成。

## 日常使用（SOP 要点）

- **申请人**：表单链接 → 选批次 → 数量 → 用途 → 提交，等群通知结果
- **审批人**：群消息点链接，或开「待审批」视图 → 经关联批次进库存表看图 → 点通过/拒绝
- **盘点修正**：直接改库存表「入库数量」，下一轮（≤30s）自动重算
- 「已批领用」勿手改（会被覆盖）；申领单删除后也自动重算

## 边界与 FAQ

- 通知延迟 ≤ 轮询间隔（默认 30s，config 可调）
- 「当前可用」是提单时快照，审批时以库存表实时数为准；超领有自动回退兜底
- 审批人明知超库存也要放行？把「入库数量」临时 +N 再批，或接受回退
- 表单里选不到批次 = 库存表没建该批次或行被删

## 故障排查

| 现象（看 journalctl -u gift-sync） | 原因                                  |
| ----------------------------- | ----------------------------------- |
| 获取 token 失败                   | app_id / app_secret 错               |
| 权限类错误码（9/1254306 等）           | 应用未加为该 Base 协作者                     |
| Webhook 发送失败                  | 群自定义机器人被删 / webhook_url 填错 / 开了签名校验 |
| 消息发了但状态没变                     | 按钮自动化没绑 / 点按钮的人无编辑权限                |
